# Measurements of quiddity 0.5.1

Every number here was measured on the released code, `v0.5.1` (`3a20dceb099f9780a5c18e1429d673ab6d5bca29`), on one
machine: a 4-vCPU `DO-Regular` Ubuntu 24.04.5 x86_64 cloud VM with 8 GB RAM, otherwise idle, on 13 November 2026.
rustc 1.99.1, release builds, four workers, uv 0.13.8, Python 3.12.3. MFInstSeg labels fingerprint
`cd1ff9695c2597ff0afaeae5a4a60b6cada810d24ff01adbf09417fbf130ccb6`. No other tool's results are reported here.

## MFInstSeg test split (9,375 models)

Face coverage, scored with `tools/as_compare/score.py`: [report](mfinstseg-v0.5.1-3a20dceb.html),
[JSON](mfinstseg-v0.5.1-3a20dceb.json), raw sweep `tools/as_compare/runs/v0.5.1-3a20dceb-test-qr.jsonl.gz`.

```sh
target/release/examples/face_claims STEPS tools/as_compare/test_ids.txt qr.jsonl 4    # 5:28 wall
python3 -I tools/as_compare/score.py LABELS qr.jsonl - scores.json --quiddity-revision 3a20dceb099f9780a5c18e1429d673ab6d5bca29 --exporter-revision 3a20dceb
```

All 9,375 models returned `ok`. Calling-thread CPU time per model: read median 12.6 ms (p95 22.9 ms);
recognition median 73.1 ms (p95 241.6 ms, maximum 39.5 s on `20221121_154648_13204`).

| Class | Recognition | Claimed faces | False positives |
|---|---:|---:|---:|
| Holes | 98.49% | 95.03% | 6.24% |
| Rounds | 89.30% | 79.47% | 0.22% |
| Any feature | 84.26% | 83.07% | 0.39% |

One-to-one matching at instance IoU >= 0.5 (`examples/mfinstseg_score.rs`, the regression-baseline metric),
with per-class true positives, false positives, false negatives, precision, recall and F1:
[iou-per-class.md](v0.5.1/iou-per-class.md), data [iou-test.json.gz](v0.5.1/iou-test.json.gz). It scored 9,371
of the 9,375 models: three are renamed duplicates whose originals lie outside the test split, and one has a
label identity that differs from its original. Over the 24 mapped classes: precision 0.860, recall 0.770, F1 0.813.
Why the weakest classes are weak: [confusion.md](v0.5.1/confusion.md).

## Robustness (a 10% sample, not the full 62,495)

Every tenth model of all 62,495 in lexical order (indices 0, 10, 20, ...; 6,250 models,
[ids](v0.5.1/robustness-10pct-ids.txt)), `examples/coverage_sweep.rs` then `tools/coverage_sweep_report.py`:
6,250 read and recognised; 0 read failures, 0 recognition failures, 0 panics. Median 0.085 s per model
(p95 0.256 s; wall time with four workers; the slowest model took 141 s). 4:39 wall.
Data: [sweep](v0.5.1/robustness-10pct-sweep.jsonl.gz), [report](v0.5.1/robustness-10pct-report.json).

## Geometry accuracy (`tools/gvp.py`, docs/geometric-validation.md)

OCP: `cadquery-ocp-novtk` 8.0.1.1.0. Inputs: quiddity-corpus `3ef06590`, dw-examples `7048eb37` NIST files,
and `tests/fixtures`. Band 0.1% (centroid distance relative to the bounding-box diagonal).
Against the validation properties stored in 18 NIST files: 103 of 106 checks pass; the three failures are
NIST STC-06, whose stored properties are zero while we and OpenCascade agree. Largest in-band errors:
volume 2.6e-5, area 8.5e-5, centroid 1.5e-6. Against OpenCascade: 2,868 files, 9,120 checks, 9,110 pass,
8 are known OpenCascade reference problems, 2 differ (one part, `14052.step`: volume 0.35%, area 0.16%).
Data: [table](v0.5.1/gvp-table.txt.gz), [evidence](v0.5.1/gvp-evidence.json.gz).

PMI read on the 15 NIST AP242 files (`quiddity pmi read`): 244 dimensions, 329 tolerances, 106 datums and 21 datum
targets, [per file](v0.5.1/haecceity-pmi-read). A fresh OpenCascade XCAF read counts differently (404, 297 and 678
labels, [counts](v0.5.1/occt-pmi-counts.jsonl)) because it makes one label per use, so the counts are not an
agreement figure; the item-by-item comparison is the repository's `pmi_read` test (`nist_expected_pmi`,
`opencascade_cross_check`), which passed at this tag (21 passed, 1 ignored).

## From Python: 0.3.12 against 0.5.1

Each in its own `uv venv --python 3.12` (`quiddity==0.3.12`: 59 packages, 876 MB; `quiddity==0.5.1`: 1 package, 25 MB).
0.3.12: `build_framed_recognition_result(import_step_geometry(path))`; 0.5.1: `quiddity.recognise(path)`.
210 parts: 10 NIST CTC/FTC parts and 200 MFInstSeg test models (every 47th id,
[ids](v0.5.1/python-compare-mfinstseg-ids.txt)). One fresh process per part and version, the versions interleaved,
median of three warm calls. All 210 succeeded in both.

| | 0.3.12 | 0.5.1 |
|---|---:|---:|
| median per part | 1.085 s | 0.096 s |
| 95th percentile per part | 3.85 s | 0.65 s |
| median peak RSS | 418 MB | 33 MB |
| import | 5.8 s | 0.02 s |
| 200-model batch, CPU | 248.7 s | 24.9 s |

Median speed-up per part 10.7x (6.9x on the ten NIST parts, 10.8x on the MFInstSeg sample). Caveats: the two find
different feature sets, read STEP with different readers (OpenCascade against haecceity's own), the 0.5.1 call
includes building the JSON text, and everything ran on one machine. Instructions retired could not be measured
(no performance counters on the VM), so CPU seconds are given. [Runs](v0.5.1/python-compare-runs.jsonl.gz),
[scripts](v0.5.1/scripts).

## Tests and counts

- Tests: `cargo test --workspace --release -- --list` at `v0.5.1` lists 1,406 test functions (1,393 run by default, 13 `#[ignore]`d) across 81 test binaries plus doc-tests.  Pass/fail of the full suite is CI's job and is not restated here.
- Rust snapshots: 2,703 committed snapshot files under `tests/fixtures/rust-snapshot` (35 top-level entries). `snapshot-tool --check` was not run: it regenerates every snapshot by replaying the producing tests (CI's `--check --coverage-only` only verifies what the shards recorded), which needs the full suite twice.
- Recognition families: the README's family table names 51 families; the robustness sweep's counts cover 46 `Features` family arrays (40 with at least one record in the 10% sample), and `face_claims` exports 41 (39 with records on the test split).
- haecceity PMI test file at this tag: `cargo test -p haecceity --release --test pmi_read` = 21 passed, 0 failed, 1 ignored.
